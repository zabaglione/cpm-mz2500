# 実機用移行FDとMIGRATE.COM

CP/M 2.2版（v1.3.2の標準HDD配置）または非バンク版
CP/M Plus v3.0.0から、バンク版v3.1.0へファイルを移す専用ツールです。
他社製CP/M、異なるパーティション配置、SASIの複数ターゲットは対象外です。

配布用の一式は`build/mz2500-migration-kit.zip`です。展開した場合、以下の
`build/`を除いた場所に各イメージがあります。

## 用意するもの

- `build/cpm_migrate.d88`を書き込んだ起動FD（A:）。作業中は抜きません。
- 書換え可能な、物理フォーマット済み640KB 2DDの退避FD（B:）。必要枚数は
  HDD走査後に表示します。上限28枚。各FDの全内容が置き換わります。
- `build/migration_blank.d88`は退避FDを事前作成するための空イメージです。
  未フォーマットFDは、同梱の`FORMAT.COM`で事前に準備できます。
- 対象HDD: EH-SASI形式、256バイトブロック、C:がLBA32、D:がLBA32800、
  各32768ブロック（8MB）。従来版と同じ接続で使用します。

MIGRATE.COMは、この起動FDのBIOS・起動バイナリに対応してビルドしています。
別版の起動FDへCOMだけ移して使用しないでください。SDカード式HDDなら、作業前に
PCでカード全体のイメージも保存しておくと、元のOS環境へ戻せます。

## 未フォーマットの退避FDを実機で準備する

1. A:の移行用起動FDからCP/M Plusを起動します。
2. B:に、消去してよい2DD FDを入れます。
3. `FORMAT B:`を実行します。ドライブ指定は必須です。
4. 消去確認に`FORMAT B:`と入力すると、物理フォーマットを開始します。
   別の文字列を入力した場合は、書き込まずに終了します。
5. `FORMAT AND VERIFY COMPLETE: 2560 SECTORS`の表示を確認します。
6. 必要枚数分、FDを交換して`FORMAT B:`を再実行します。準備できたら`MIGRATE`へ進みます。

対象FDDは`FORMAT A:`または`FORMAT B:`で指定します。確認入力も対象を含む
同じ文字列です。指定なし、C:・D:などのHDD指定、不正な引数は受け付けません。
現在の対応範囲は内蔵FDDのA:/B:です。外付けFDDの選択には対応していません。

A:をフォーマットする場合は、`FORMAT A:`を読み込んで確認待ちになってから、
A:の起動FDを消去対象のFDへ交換してください。確認入力後は、そのFDの内容が
消去されます。作業終了後に起動FDを戻してから次のプログラムを実行してください。
確認待ちに入る前に、OSの保留中の書き込みを完了させています。

80シリンダー・両面・16セクター・256バイト、MFM/250kbps/300rpmの640KB形式です。
画面の`C/H`はシリンダー・面で、16進数表示（最終位置は`4F/01`）です。
セクター構造とCRCを作成し、各面の16セクターを読んで全256バイトを照合します。

未挿入、書き込み禁止、シーク失敗、転送タイムアウト、読戻し不一致では停止します。
`ERROR`が出たFDは退避に使わず、原因を解消して最初からやり直してください。
作業中にFDを抜かないでください。フォーマット済みFDへ実行した場合も全内容を消去します。

このツールは退避用の物理フォーマットを作成します。CP/Mで一般のデータFDとして
利用するための論理初期化は行いません。エミュレータで検証済みですが、実機での
磁気記録・ドライブや媒体ごとの差異は未検証です。

## 操作

1. A:の移行用FDから起動し、`MIGRATE`を実行します。
2. `B`（BACKUP）を選びます。旧HDDの形式・ディレクトリー・割当てを検査し、
   新形式と新版システムファイルに必要な空き容量を確認します。
3. 表示された番号をラベルに書いた退避FDをB:へ入れ、`WRITE`と入力します。
   書込後に読戻しCRCを照合します。必要枚数分繰り返します。
4. `V`（VERIFY）を選びます。退避FDを1巻から順に入れ、各巻で`READ`と入力します。
   全巻・全内容の検証が終わるまでHDDを変更しません。
5. `R`（RESTORE）を選び、表示を確認して`ERASE`と入力します。
   **ここからC:/D:の内容を置き換えます。** 以後、元HDDを旧OSで使わないでください。
6. 再び退避FDを1巻から順に入れ、各巻で`READ`と入力します。各8KBのCRC確認後に
   HDDへ書き、読戻して比較します。全ファイルの復元後、A:から新版の標準システム
   コマンドを導入・検証し、最後にHDDの有効な起動ヘッダーを書き込みます。
7. `MIGRATION COMPLETE`の表示後にA:を取り出し、IPLでHDD起動します。

入力は大文字・小文字を区別しません。確認文字列が違う場合は中止します。
メニューの`Q`で終了できます。処理中にFDを抜かず、交換の表示を待ってください。

## 引き継ぐものと置き換えるもの

- C:/D:のユーザー領域0～15、ファイル内容（128バイトレコード単位）、
  ディレクトリーに記録されたファイル属性を引き継ぎます。
- 割当てブロックを詰め直すため、旧形式の末尾にあったファイルも移せます。
- C:のユーザー0にある標準ユーティリティ（CCP.COM、PIP.COM、DATE.COMなど）と
  PUTSYS.COMは、復元後に起動FDの新版へ置き換えます。旧ファイル内容も退避FDには
  保存されています。利用者ファイルが同名なら、この置換対象になります。
- 削除済みファイル、旧OSの起動領域、CP/M 3の日付印・パスワード等の拡張
  ディレクトリーレコードは引き継ぎません。対応外の記録は書込前の検査で拒否します。
- 未割当ての穴を含むランダムアクセスファイルや、記録長を超える先行割当ては
  対応外です。該当する場合はBACKUPの検査で中止し、HDDは変更しません。
- 空き容量は新版ファイル分を余裕として要求します。満杯に近いHDDでは中止し、
  元環境で不要ファイルを整理する等の対応が必要です。

## 失敗した場合

BACKUP/VERIFYでの失敗ならHDDは変更しません。退避途中の巻は有効なヘッダーが
ない状態にしてから書き始めるため、未完了巻を完成した巻として受け入れません。

RESTORE開始後の失敗・電源断では、HDDは不完全な状態になります。移行FDで再起動し、
**Vで全巻を再検証してからRを最初から実行**してください。途中再開ではなく、
退避データからのやり直しです。完了するまで退避FDを消去・再利用しないでください。

CRCは誤読・媒体破損・巻の取り違え検出用です。悪意ある改変を防ぐ署名ではありません。

## ビルドとPC上の検証

CP/M本体のPython 3・z80asmに加えてSDCC（sdcc、sdasz80）が必要です。

```sh
make migration
python3 tools/migration_archive.py volume-1.d88 volume-2.d88
```

PC用の上記コマンドは番号順に指定した全巻を検証する読出し専用ツールです。
退避FDはCP/Mファイルシステムではありません。DIRやPIPでは読み出せません。

再現用の実行テストは人工HDDを作り、実際のMIGRATE.COMをZ80として実行します。
プロジェクト所有のネイティブコアをリンクします。ROMは必要ありません。

```sh
python3 tools/make_migration_fixtures.py
c++ -std=c++17 -O2 -I /path/to/emulator -I /path/to/emulator/vendor \
  tools/verify_migration.cpp /path/to/emulator/build/native/libmz2500_core.a \
  -o build/verify_migration
build/verify_migration .
python3 tools/check_migration_result.py
```

検証ランナーは64ビットのCPUサイクルカウンターを要求します。Webエミュレータも
同じ64ビット幅に統一しました。旧WASM版の32ビット桁あふれによる長時間停止は、
今回のWeb更新で修正しています。

今回の実行確認はCP/M 2.2配置の人工HDDで行っています。非バンク版v3.0.0配置は
読出し処理を備えていますが、この通し実行の対象には含めていません。

静的検査・エミュレータ実行と実機での書込確認は別です。**実機での移行は未検証**です。
最初の実機確認は、重要なデータを入れていない複製HDD・SDカードで行ってください。

## フォーマッターの実装根拠と検証

Fujitsu MB8876A/MB8877AのWRITE TRACKとMFM制御バイト（F5/F6/F7）は
[メーカーのデータシート](https://www.tim-mann.org/max80/Appendix_D_Updated.pdf)の
IBM System 34形式を基にしています。MZ-2500のレジスター極性・ドライブ選択は
本プロジェクトの既存BIOSとSHARP資料に基づきます。EmuZ/CSCPソースは使用していません。

`make migration`でFORMAT.COMもビルドし、起動FDとZIPへ同梱します。
次のランナーは未フォーマット媒体からの作成、MIGRATEによる退避・全巻検証、
キャンセル、未挿入、書込禁止、途中取り出しを確認します。対象外のFDDとHDDの不変も照合します。A:のフォーマットと引数・確認ドライブの拒否も検証します。

```sh
c++ -std=c++17 -O2 -I /path/to/emulator -I /path/to/emulator/vendor \
  tools/verify_format.cpp /path/to/emulator/build/native/libmz2500_core.a \
  -o build/verify_format
build/verify_format .
python3 tools/check_format_result.py
```
